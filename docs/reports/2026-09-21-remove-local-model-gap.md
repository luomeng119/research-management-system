# 科研管理系统去本地模型与源码交付：差异分析

## 目标基线

当前交付应作为不依赖本地生成模型的科研管理系统运行：业务人员可登录、管理项目和资料、人工编辑科研报告、维护版本及敏感词并导出 DOCX。项目模型资产不存在，AI 入口默认不展示，相关路由不可直接使用；实现代码保留在仓库中供以后受控启用。

## 差异矩阵

| 领域 | 当前状态 | 目标状态 | 修复动作 | 验证 |
| --- | --- | --- | --- | --- |
| 模型资产 | 项目目录约 20.94 GiB，含完整模型与下载分片 | 项目模型目录及碎片清零 | 精确删除项目模型目录，复核其他项目模型 | 删除前后清单、大小与保护路径检查 |

## API 兼容性

- 现有人工业务 URL、报告查看编辑、版本、敏感词维护和 DOCX 导出保持不变。
- AI 专用 URL 在 `AI_FEATURES_VISIBLE=False` 时统一返回 404；这是当前交付的预期能力边界。
- 以后恢复 AI 时需同时显式开启可见性、选择 provider，并配置对应运行器；单独设置 provider 不应绕过产品总门禁。

## 威胁模型与隐私边界

1. 模型文件和下载分片会造成仓库体积失控，必须从文件系统与 Git 入口同时排除。
2. 数据库、上传资料、会话、日志和本机证据可能包含业务数据或身份信息，不进入源码仓库。
3. 环境变量、密钥文件、token 和凭据不得提交；发布前扫描当前树和全部历史。
4. 隐藏功能必须以后端门禁为准，避免仅靠前端隐藏造成未授权直接调用。
5. GitHub 协作者使用各自账号；不共享所有者凭据。

## 观测与运行说明

本轮不新增生产遥测。可验证状态由健康检查、路由返回码、测试报告、仓库文件清单、克隆复核和 GitHub API 回读提供。
