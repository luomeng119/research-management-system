# 领导介绍页与登录页现状审计

## 当前事实

- 运行入口固定为 `http://127.0.0.1:8893/auth/login`，应用、模型和 PostgreSQL 分别使用 8893、18081、58562 端口。
- `app/templates/login.html` 已有账号密码表单、CSRF 字段、错误提示和科研业务主线，但视觉层次较弱，没有系统介绍入口。
- `app/__init__.py` 通过 `PUBLIC_ENDPOINTS` 控制公开页面，除登录、静态资源和健康检查外，业务页面必须登录。
- 当前前端为 Flask/Jinja 服务端页面，使用本地 Bootstrap、图标、字体和脚本，不依赖外网资源。
- 当前本地模型为 Qwen3.5-9B Q8，通过 llama.cpp 的 OpenAI 兼容 HTTP 接口运行；“OpenAI 兼容”仅指调用协议，不是云端 OpenAI 服务。

## 当前业务与 AI 边界

- 程序规则负责：账号与权限、项目状态、资料存储、敏感词确定性替换、版本记录、审计和导出。
- 本地 AI 参与：提案内容辅助、图片资料理解、多个来源整合成报告草稿、框选文字的候选替换建议。
- 人工确认负责：采用建议、修改正文、确认最终版本和导出结果。

## 风险边界

- 介绍页不得展示业务数据、口令或后台连接信息。
- 介绍页不得引用 CDN、远程图片或第三方统计脚本，现场无网时必须完整可用。
- 登录页改造必须保留字段名、字段 ID、CSRF、错误反馈和提交行为。
- 不改变现有端口、数据库、模型进程和业务路由。

## 审计结论

采用“新增独立公开介绍页 + 小幅优化现有登录页”的渐进式改造，修改范围可控且可通过删除新增路由/模板/静态资源回滚。
