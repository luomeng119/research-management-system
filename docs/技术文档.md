# 科研管理系统 — 技术文档

> 面向接续开发团队的系统技术说明。涵盖架构、技术栈、模块划分、数据库设计、关键机制与部署方式。

---

## 1. 系统架构

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器（内网客户端）                    │
│              HTML/CSS/JS + 本地化 Quill 编辑器            │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP (Jinja2 模板渲染 + 少量 JSON API)
┌──────────────────────────▼──────────────────────────────┐
│                    Flask 应用（app/）                     │
│  ┌────────────────────────────────────────────────────┐  │
│  │  create_app() 工厂函数（app/__init__.py）           │  │
│  │  · 注册 22 个 Blueprint                             │  │
│  │  · Flask-Session + cachelib 本地文件存储       │  │
│  │  · 启动时不执行 DDL、不创建默认账户          │  │
│  └────────────────────────────────────────────────────┘  │
│  ├── routes/        20+ 功能模块路由                     │
│  ├── repositories/  PostgreSQL 数据访问                  │
│  ├── services/      业务服务                            │
│  ├── llm/           本地大模型（校对/检索，懒加载）        │
│  ├── ocr/           RapidOCR 识别                        │
│  └── utils/         模糊匹配 / 导入进度                   │
└──────────┬───────────────────────────────┬──────────────┘
           │                               │
   ┌───────▼────────┐              ┌───────▼────────┐
   │ PostgreSQL 主库 │              │ DeepSeek API     │
   │ 127.0.0.1      │              │ (可选在线增强) │
   │ Alembic 迁移    │              │ 断网不阻断业务  │
   └────────────────┘              └────────────────┘
```

**架构要点**：

- **单体 Flask 应用**，无前后端分离（服务端渲染 Jinja2 模板 + 少量 JSON API）
- **PostgreSQL 单库**：SQLAlchemy Core 数据访问，Alembic 管理结构迁移；旧 SQLite 多库只作一次性迁移输入
- **模块化 Blueprint**：路由、服务与仓储分层，保留现有功能边界
- **可选 AI 能力**：V1 可配置 DeepSeek 在线 API 辅助提案；不可用时回退为手工填写，不阻断核心业务

## 4. 数据库设计

正式 V1 使用一个本地 PostgreSQL 业务库，设备、项目、专家、资源、经费登记、文件元数据与通用表格均通过 SQLAlchemy Core 仓储访问，由 Alembic 统一迁移。

### 关键设计约束

- **多版本表 UPDATE/DELETE 必须带 version_id**：通用表格的 `generic_table_data` 用 `UNIQUE(version_id, row_key)` 复合约束，但任何 UPDATE/DELETE 的 WHERE 必须同时带 `row_key` 和 `version_id`，否则会跨版本误改（历史 bug）。
- **DB 路径看模块**：每个模块的 DB 路径在对应 `models_*.py` 的 `DB_PATH` 常量里定义，改/查前先 `grep "DB_PATH" app/models_*.py` 确认。

## 5. 关键机制

### 5.1 Session（cachelib 本地文件存储）

`app/__init__.py` 使用 Flask-Session filesystem 存储替代 cookie session：

- 原因：批量导入 1200+ 条数据时，`session['equipment_import_preview']['processed']` 超过 cookie 4KB 限制
- session 文件存 `data/flask_sessions/`
- `SESSION_USE_SIGNER = True`（签名防篡改）
- **教训**：Flask session 为「小数据 + 签名」设计，大数据量走临时文件或 DB

### 5.2 批量导入（分步 + 临时文件）

批量导入 Excel 流程（设备/专家/主机设备通用）：

1. 上传解析 → 存临时文件（`task_id.json`，避免 session 超限）
2. 分步渲染（列映射 → 预览 → 确认）
3. 提交时事务回滚 + 清理临时文件

### 5.3 文档预览

- Word：python-docx 提取文字
- Excel：openpyxl 读单元格
- PDF：pdfminer/PyMuPDF
- 图片：直接展示
- **不依赖 LibreOffice**（内网离线约束）

### 5.4 OCR 识别

- RapidOCR（onnxruntime）为可选依赖，实际 OCR 使用时通过 `_get_rapid_ocr()` 懒加载；依赖缺失不阻断 Flask 启动

### 5.5 AI（可选）

- `AI_PROVIDER=DEEPSEEK` 且配置 API key 时，提案助手可调用在线 DeepSeek API
- 外发前必须由用户明确确认；助手草稿必须再由人工选择字段采纳
- 未配置、断网、超时或服务不可用时，提案及其他核心功能仍可手工完成
- 原 `app/llm/` 本地校对/检索代码保留但默认关闭，不是 V1 核心验收项

## 6. 部署方式

### 6.1 本地开发

```bash
pip install -r requirements.txt
python run.py          # 监听 127.0.0.1:5001
```

### 6.2 内网离线部署

1. 在 Windows x64 联网构建环境中，使用 `scripts/build_offline_bundle.py` 基于真实运行件生成并验证 `offline/`；仓库中没有占位运行包
2. 在目标机设置空的本地 NTFS 目录：`$env:APP_DATA_ROOT = 'C:\ResearchManagementData'`
3. 执行 `powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1 -OfflineRoot .\offline`
4. 执行 `powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1`；停止使用 `scripts/stop.ps1`
5. 在干净目标机执行 `scripts/acceptance.ps1 -OfflineRoot .\offline -EvidenceRoot .\build\acceptance`，保留安装、核心业务、备份、空环境恢复、重启和浏览器级请求证据。系统级零外联还必须在真实断网环境中，或通过防火墙、抓包和连接审计另行取证；当前未完成该实机验收

> 当前 `start.ps1`/`stop.ps1` 管理用户态 PostgreSQL 和 Waitress 进程。是否改为 Windows 服务及开机自启仍需产品方确认，本节不宣称已完成该部署目标。

### 6.3 端口说明

- Waitress 应用默认监听 **127.0.0.1:5001**，可通过 `APP_BIND_HOST`/`APP_PORT` 调整
- 本地 PostgreSQL 离线安装默认监听 **127.0.0.1:55432**
- DeepSeek 为可选外部 API，未启用时不需要额外本地 AI 端口

## 7. 性能与安全要点

### 性能

- 批量导入 1200+ 条数据需分步 + 临时文件，不能塞 session
- V1 Waitress 按单进程、4 线程运行；不为可选 AI 预留本地模型内存预算
- OCR 为可选依赖，在实际使用时加载；依赖缺失不阻断 Flask 启动
- 检索/筛选必须即时响应（监听 `input` 事件，不等回车）

### 安全

- 密码 bcrypt 哈希
- session 签名（`SESSION_USE_SIGNER`）
- 系统不创建默认管理员；首个管理员必须由部署流程显式初始化
- 非测试环境必须通过环境变量 `FLASK_SECRET_KEY` 提供稳定密钥，未配置时拒绝启动
- 权限：管理员可见全部目录，普通用户按 `get_directory_permissions` 过滤
