# 科研管理系统 — 技术文档

> 面向接续开发团队的系统技术说明。涵盖架构、技术栈、模块划分、数据库设计、关键机制与部署方式。

---

## 1. 系统架构

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器（内网客户端）                    │
│              HTML/CSS/JS + 本地化 Quill 编辑器            │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP (Jinja2 模板渲染 + 少量 JSON API)
┌──────────────────────────▼──────────────────────────────┐
│                    Flask 应用（app/）                     │
│  ┌────────────────────────────────────────────────────┐  │
│  │  create_app() 工厂函数（app/__init__.py）           │  │
│  │  · 注册 22 个 Blueprint                             │  │
│  │  · Flask-Session（filesystem）                     │  │
│  │  · 启动时不执行 DDL、不创建默认账户          │  │
│  └────────────────────────────────────────────────────┘  │
│  ├── routes/        20+ 功能模块路由                     │
│  ├── models*.py     数据模型（原生 sqlite3）              │
│  ├── llm/           本地大模型（校对/检索，懒加载）        │
│  ├── ocr/           RapidOCR 识别                        │
│  └── utils/         模糊匹配 / 导入进度                   │
└──────────┬───────────────────────────────┬──────────────┘
           │                               │
   ┌───────▼────────┐              ┌───────▼────────┐
   │  SQLite 数据库  │              │  Node.js 推理   │
   │  data/*.db     │              │  服务器(可选)    │
   │  · research.db │              │  端口 18789     │
   │  · generic_    │              │  GGUF 模型      │
   │    tables.db   │              │  (文档校对)     │
   └────────────────┘              └────────────────┘
```

**架构要点**：

- **单体 Flask 应用**，无前后端分离（服务端渲染 Jinja2 模板 + 少量 JSON API）
- **无 ORM**，所有数据访问用 Python 标准库 `sqlite3`，SQL 手写
- **模块化 Blueprint**：每个业务模块一个路由文件，模型文件按域拆分
- **可选 AI 能力**：本地 GGUF 模型推理走 Node.js 独立进程（不阻塞 Flask），懒加载

### 关键设计约束

- **多版本表 UPDATE/DELETE 必须带 version_id**：通用表格的 `generic_table_data` 用 `UNIQUE(version_id, row_key)` 复合约束，但任何 UPDATE/DELETE 的 WHERE 必须同时带 `row_key` 和 `version_id`，否则会跨版本误改（历史 bug）。
- **DB 路径看模块**：每个模块的 DB 路径在对应 `models_*.py` 的 `DB_PATH` 常量里定义，改/查前先 `grep "DB_PATH" app/models_*.py` 确认。

## 5. 关键机制

### 5.1 Session（filesystem 存储）

`app/__init__.py` 使用 Flask-Session filesystem 存储替代 cookie session：

- 原因：批量导入 1200+ 条数据时，`session['equipment_import_preview']['processed']` 超过 cookie 4KB 限制
- session 文件存 `data/flask_sessions/`
- `SESSION_USE_SIGNER = True`（签名防篡改）
- **教训**：Flask session 为「小数据 + 签名」设计，大数据量走临时文件或 DB

### 5.2 批量导入（分步 + 临时文件）

批量导入 Excel 流程（设备/专家/主机设备通用）：

1. 上传解析 → 存临时文件（`task_id.json`，避免 session 超限）
2. 分步渲染（列映射 → 预览 → 确认）
3. 提交时事务回滚 + 清理临时文件

### 5.3 文档预览

- Word：python-docx 提取文字
- Excel：openpyxl 读单元格
- PDF：pdfminer/PyMuPDF
- 图片：直接展示
- **不依赖 LibreOffice**（内网离线约束）

### 5.4 OCR 识别

- RapidOCR（onnxruntime），启动时 `_get_rapid_ocr()` 预加载，避免首次调用等待

### 5.5 AI 推理（可选）

- 本地 GGUF 模型 + Node.js 推理服务器（`inference_server.js`，端口 18789）
- `run.py` 异步启动（后台线程，不阻塞 Flask）
- 缺 node / 模型文件时自动跳过，仅文档校对/智能检索不可用
- 模型懒加载，全局单例 `app.llm.get_pool()`

## 6. 部署方式

### 6.1 本地开发

```bash
pip install -r requirements.txt
python run.py          # 监听 127.0.0.1:5001
```

### 6.2 内网离线部署

1. 准备 Python 3.13 环境（或携带 `offline_packages/` 离线包）
2. 安装依赖：`offline_packages/install.bat`（Windows）或手动 `pip install --no-index --find-links=offline_packages/packages -r requirements.txt`
3. 部署时显式配置并持久保管稳定的 `FLASK_SECRET_KEY`（多实例使用同一值）
4. 通过受控的初始化流程准备数据库结构、基础数据和首个管理员
5. 启动：`python run.py`

### 6.3 端口说明

- Flask 默认监听 **5001**（`run.py` 内硬编码）
- 推理服务器端口 **18789**（`run.py` 内硬编码）
- 部署到多台机器时，注意容器内启动的 Flask 无法从宿主机外部直接访问（网络命名空间差异），需在目标机器本地启动

## 7. 性能与安全要点

### 性能

- 批量导入 1200+ 条数据需分步 + 临时文件，不能塞 session
- LLM 双模型（1.5B Q4 ×2）约 3~4GB 内存，建议单 worker
- OCR 为可选依赖，在实际使用时加载；依赖缺失不阻断 Flask 启动
- 检索/筛选必须即时响应（监听 `input` 事件，不等回车）

### 安全

- 密码 bcrypt 哈希
- session 签名（`SESSION_USE_SIGNER`）
- 系统不创建默认管理员；首个管理员必须由部署流程显式初始化
- 非测试环境必须通过环境变量 `FLASK_SECRET_KEY` 提供稳定密钥，未配置时拒绝启动
- 权限：管理员可见全部目录，普通用户按 `get_directory_permissions` 过滤
