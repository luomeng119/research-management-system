**关键认知**：

- `app/templates/` 是源码模板，**根目录的 `templates/` 是科研模板数据目录**（用户上传的模板文件，两者别混）
- 正式运行数据使用 PostgreSQL，应用文件位于 `APP_DATA_ROOT`；`data/` 中的 SQLite 文件仅是旧数据迁移/兼容输入，不是 V1 正式运行库
- 每个需求在 `SPEC/01-需求/` 下独立成目录，含 4 个文档

## 2. 环境准备与启动

### 2.1 依赖安装

```bash
# 联网
pip install -r requirements.txt
```

```powershell
# Windows x64 离线部署（需已验证的 offline/ 完整运行包）
$env:APP_DATA_ROOT = 'C:\ResearchManagementData'
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1 -OfflineRoot .\offline
```

### 2.2 启动

```bash
# 本地开发；正式部署使用 scripts/start.ps1
export DATABASE_URL='<PostgreSQL 连接地址>'
export FLASK_SECRET_KEY='<由部署环境安全保管的稳定随机值>'
python run.py
```

- 监听 `127.0.0.1:5001`
- 非测试环境未配置 `FLASK_SECRET_KEY` 时拒绝启动；多实例必须使用同一值
- 应用工厂不执行 DDL，也不创建默认用户；数据库与首个管理员由部署初始化流程显式准备
- 离线部署完成后使用 `scripts/start.ps1` / `scripts/stop.ps1`；目前为用户态进程，Windows 服务/开机自启尚未定案
- 真实离线验收使用 `scripts/acceptance.ps1 -OfflineRoot .\offline -EvidenceRoot .\build\acceptance`，必须在 Windows x64 且断网或有系统级出站证据的环境执行

### 2.3 启动验证

```bash
# 未登录访问列表页，期望 HTTP 302（跳转 /auth/login = 服务正常）
curl -s -o /dev/null -w "HTTP=%{http_code}\n" http://127.0.0.1:5001/equipment/
```

- HTTP 302 → 服务正常（未登录）
- HTTP 200 → 列表正常
- HTTP 000 / connection refused → 服务没起来

### 2.4 常见启动问题

| 症状 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: flask_socketio` | 用了系统 Python 而非项目 venv | 用 `./venv/bin/python run.py` |
| 端口不响应但进程在 | 历史版 `run.py` 曾同步等待推理服务 | 当前 `run.py` 只启动 Waitress；可选 AI 不得成为启动前置 |
| 改了 .html 不生效 | Flask 模板缓存（debug=False） | 重启 Flask |

## 3. 开发流程（SPEC 规范）

项目采用 SPEC 驱动的开发流程，每个需求经过 6 阶段：

```
①需求捕获 → ②需求设计（6维度） → ③UI设计（ASCII图） → ④代码设计 → ⑤编码（自测后才通知） → ⑥验收交付
```

**文档产出**（每个需求 REQ-NNN 在 `SPEC/01-需求/REQ-NNN/` 下 4 个文档）：

| 文档 | 内容 |
|---|---|
| REQ-NNN-用户需求.md | 用户原始需求 |
| REQ-NNN-需求设计.md | 6 维度设计 |
| REQ-NNN-UI设计.md | ASCII 图 UI 设计 |
| REQ-NNN-代码设计.md | 代码结构设计 |

验收报告在 `SPEC/03-验收交付/VAL-NNN.md`。

**SPEC 协作规则**：用户可直接改 SPEC 文档——小改自改不提；中改改完简述；大改先商量。

## 4. 测试方法

### 4.1 单元/集成测试

项目用 pytest，测试在 `app/tests/`：

```bash
cd 项目根目录
python -m pytest app/tests/ -v
```

### 4.2 无浏览器验证 Flask 路由（test_client）

```python
import os, sys
os.chdir('项目根目录')  # 关键：先切 cwd，否则 sqlite 相对路径找不到 DB
sys.path.insert(0, '项目根目录')
from app import create_app
app = create_app()

with app.test_client() as c:
    # 用 session_transaction 直接写 session，绕过登录
    with c.session_transaction() as sess:
        sess['user'] = 'admin'
        sess['name'] = '管理员'
        sess['role'] = '管理员'
    resp = c.get('/equipment/?category=安全设备')
    print(f'HTTP={resp.status_code}  size={len(resp.data)}')
    for kw in ['TypeError', 'Traceback', 'Error on']:
        assert kw not in resp.data.decode('utf-8', errors='replace')
```

### 4.3 真实浏览器验证（Playwright）

改 UI/模板交互细节时，用 test_client 准备 session cookie → Playwright 真实点击验证。详见 `ERROR_KNOWLEDGE.md` 的 P6 章节。

### 4.4 测试铁律

1. **自测「全部通过」必须基于真实 UI 流程**（Playwright 端到端走完整按钮链），不是 curl/requests 模拟
2. **每次 Bug 修复或新功能上线后必做全功能回归测试**
3. **测试数据要语义匹配**：姓名列填人名、班级列填班级名；用户报 bug 但复现不出来时优先查数据语义

## 5. 开发规范（精华）

完整规范见 `ENGINEERING_REQUIREMENTS.md`，核心几点：

### 数据库访问

- **禁止位置索引**（r[0]/r[1]），必须 `SELECT *` + `cursor.description` + `dict(zip(cols, row))` 按字段名访问
- **禁止依赖表列顺序**（`ALTER TABLE ADD COLUMN` 会错乱）
- 多版本表 UPDATE/DELETE 必须带 `version_id`

### 前端

- 检索/筛选**即时响应**（监听 `input` 事件，不等回车）
- HTML 标签嵌套规范（ul>li>ul）
- **前端资源本地化**，禁止外网 CDN

### 内网约束

- 文档预览**不依赖 LibreOffice**，用纯 Python 库
- Quill 编辑器已本地化（`/static/quill/`）

### 提交规范

- commit 前**先 `git status --short` 看清单**，禁止 `git add .`（会带入运行时文件）
- 该忽略的：`data/operation_logs.json`、`__pycache__/`、`test_data/`、`*.db`

## 6. 踩坑记录（必读）

以下是从 18+ 个历史 bug 提炼的核心教训，完整版见 `ERROR_KNOWLEDGE.md`（48KB）：

### P1. 可选依赖启动不能阻塞主进程
这是历史问题记录。当前 `run.py` 不再启动推理服务器；可选 AI 不得阻断 Waitress 和核心业务启动。

### P4. 开发容器 ≠ 部署目标机器
容器内启动的 Flask 无法从宿主机外部访问（网络命名空间差异）。报「访问不了」先 `hostname -I` 确认自己 IP 是否等于用户访问的 IP。

### P8. 改 .html/.py 后必须重启 Flask
`debug=False` 时 Jinja2 缓存模板、Python 字节码不重载。**改了模板/Python 看不到效果 = 第一时间重启**。静态资源（CSS/JS）改完浏览器强刷即可。

### P9. 历史 SQLite 迁移源的索引诊断
旧版 SQLite 数据源曾因并发写入/异常断电出现 `sqlite_autoindex_*` 错位。下列命令只用于迁移前诊断旧 `generic_tables.db`，不是 V1 PostgreSQL 正式库的业务运维方式：
```bash
python3 -c "import sqlite3; print(sqlite3.connect('data/generic_tables.db').execute('PRAGMA integrity_check;').fetchall())"
```

### P10. 中文路径 + 后台启动的 workdir 坑
`terminal(background=true, workdir='中文路径')` 会报 `disallowed character`。中文路径必须用单引号包起来 + `cd ... && command` 串成一行。

### P11. 历史 SQLite 诊断脚本的相对路径
旧诊断脚本若使用 `sqlite3.connect('data/research.db')`，必须先确认工作目录。该经验只适用于旧数据迁移/诊断，V1 正式业务应使用配置的 PostgreSQL 连接与仓储。

### P12. Flask session 4KB 上限
批量操作（导入 1000 条）数据不能塞 session。**走临时文件 + task_id 方案**：解析后存 `task_id.json`，session 只存 32 字节 task_id。

### P13. 修复用户可见行为必须遍历所有层
一个行为由「SQL/模型 → 路由 → 模板 → JS」多层决定，任一层硬编码会短路下层修复。修 label/名称/状态/默认值/权限/格式类问题时，**先列所有层清单，逐层 grep 硬编码**，再用 Playwright 真实验证。

### P14. SQL 多版本表 UPDATE/DELETE 必须带 version_id
```sql
-- ❌ 错（跨版本误改）：
UPDATE table SET col=? WHERE row_key=?
-- ✅ 对：
UPDATE table SET col=? WHERE row_key=? AND version_id=?
```
`UNIQUE(version_id, row_key)` 只防 INSERT 重复，**不防 UPDATE 跨版本**。

### P16. git status 先看再 add
禁止 `git add .`。commit 前 3 步：`git status` 看清单 → 分类该不该提交 → 精确 `git add 具体文件` → `git status --short` 核对。

### P17. pytest fixture 污染
e2e 测试通过 test_client 走真实 DB，会持久化全局配置残留。**任何「测试期间改了全局配置」的 e2e 测试 → autouse fixture 每个 test 前重置**。
