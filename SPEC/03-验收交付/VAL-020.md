## 5. 关键设计决策落地情况

| 设计决策 | 实现情况 | 证据 |
|---|---|---|
| 引入 current_version 概念 | ✓ | generic_tables.current_version_id 字段 + init_db 自动迁移 |
| 表格永远有可编辑 current | ✓ | init_db 规则 1 取最大 is_locked=0 版本；create() 直接指向 v1 |
| 快照是历史存档（is_locked=1） | ✓ | create_version method=snapshot is_locked=1 |
| create 是可编辑（is_locked=0） | ✓ | create_version method=create is_locked=0 |
| import/rollback 内部用复制 working 副本 | ✓ | create_version method in ('snapshot','import','rollback') 都从 source 复制列+数据；只有 snapshot is_locked=1 |
| save_snapshot = 复制 source 为 snapshot + 复制 source 为新 working + 更新 current | ✓ | models_generic_tables.py save_snapshot() 三步事务 |

| 导入数据不再自动建"导入前存档" | ✓ | detail.html importExcelNew() 去掉"先建 snapshot"逻辑 |
| 导入到非 current 返回 403 | ✓ | routes api_rows_import 校验 is_locked=0 |

## 7. 已知限制

- 路由末尾带斜杠（`/version/<id>/`）是 Flask 严格要求，**前端生成的 URL 都带 /**，老 URL `?version=<id>` 兼容但不带斜杠的路径会 404
- 路径含特殊字符（如 `&` `<` `>`）的快照 label 可能在弹窗 confirm 里有显示问题（转义没做）
- `addRow()` 等 JS 函数定义在只读模式仍存在（只是 onclick 不渲染），体积可忽略
- save_snapshot 大量行复制性能：1 万行约几百毫秒，前端 loading 遮罩未做（连续点击可能 race condition）

## 8. 后续优化建议（非本期范围）

- save_snapshot 前端加 loading 遮罩
- 路径含特殊字符的快照 label 在 confirm 弹窗里做转义
- 文档校对功能恢复：当前 chpt_corrector 离线 GGUF 模型仍缺失（与 REQ-020 无关，是老问题）
- 通用表格导入数据量上限提示（当前无限制，可能 OOM）
- 历史快照删除功能（当前 delete_version API 存在但 UI 没接）
