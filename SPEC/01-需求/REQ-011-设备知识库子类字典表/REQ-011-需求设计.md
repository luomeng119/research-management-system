# REQ-011 需求设计

**状态：阶段二（需求设计）— 已确认**

---

## 1. 用户描述复述

为设备知识库的三大类（密码设备、安全设备、通用设备）增加二级子类分类，属性的值来自独立字典表。导入时出现新子类由用户确认后新增；编辑/新增页面子类为下拉选择。

---

## 2. 功能理解

- **本质**：给设备知识库增加一个二级分类维度（设备子类），属性值受控于独立字典表
- **导入场景**：Excel 中可能出现字典中没有的新子类，需要用户确认后才写入字典
- **编辑/新增场景**：子类是下拉选择，选项随分类切换动态变化
- **列表场景**：支持按子类筛选项，筛选器与分类联动

## 5. 流程

### 5.1 导入流程（新增子类确认）

```
步骤1: 上传 Excel
步骤2: 预览 + 匹配状态标注
        ├─ 精确匹配 → 绿色文本
        ├─ 模糊匹配 → 黄色文本
        ├─ 待新增 → 橙色文本 + [确认]/[跳过] 按钮
        └─ 空值 → 灰色文本
       点击「下一步」→ 弹出集中确认框（显示所有待新增子类列表）
       用户确认 → 步骤3提交，新子类写入字典表
步骤3: 提交入库
```

### 5.2 编辑/新增流程

```
选择分类 → 子类下拉自动刷新为该分类下的子类选项 → 选择或留空
```

### 5.3 列表筛选流程

```
选择分类 → 子类筛选项自动刷新 → 可选填子类 → 确认筛选
```

## 7. 数据库设计

### 7.1 新增表：knowledge_subclasses

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| parent_category | VARCHAR(50) | NOT NULL | 父分类（密码设备/安全设备/通用设备） |
| subclass_name | VARCHAR(100) | NOT NULL | 子类名称 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**唯一约束**: `UNIQUE(parent_category, subclass_name)`

### 7.2 修改表：equipment

新增字段：
- `subclass` VARCHAR(100) DEFAULT '' — 设备子类

## 8. 模糊匹配逻辑

`match_subclass()` 与 `match_research_unit()` 逻辑完全一致：

1. **精确匹配** (`exact`)：字典中 name == 输入
2. **别名匹配** (`alias`)：输入 in aliases（如果有别名表）
3. **规范化匹配** (`normalized`)：去除噪声后 substring 匹配
4. **模糊匹配** (`fuzzy`)：编辑距离 <= 2
5. **均无** (`none`)：未匹配

> 注意：`[vV]\d+` 噪声正则会去掉版本号（如 V3），导致"密码机V3改进型"清理后变成"密码机改进型"无法匹配"密码机V3"。这是已知问题，暂不在本需求范围内修复。
