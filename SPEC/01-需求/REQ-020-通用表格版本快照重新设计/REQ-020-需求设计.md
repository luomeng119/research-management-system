# REQ-020 需求设计

## 1. 用户描述复述

> 04 科研管理系统，通用表格管理模块，关于版本和快照的关系，要重新设计。目前新建一个表格，然后进行数据导入，默认就是快照状态，不可编辑，导致没有办法往下进行业务流程了。

**关键约束**（用户选择的设计方向 B）：
- 引入"编辑态"概念
- 表格永远有 current_version（可编辑）
- 快照是历史存档（只读）
- 所有编辑/导入/回滚操作都在 current_version 上

## 2. 功能理解

**当前问题**（基于代码分析）：

前端 `detail.html` line 770-781 的导入流程：

```
用户点"导入"
  ↓
前端先调 POST /versions 创建一个 method='snapshot' 的"导入前存档"
  ↓
这个新快照 is_locked=1（REQ-019 的自动锁定规则）
  ↓
数据导入到这个新快照里
  ↓
用户看到的是 locked 版本，编辑不了
```

每次导入都先建一个 locked 快照，再把数据导入到 locked 快照里。**逻辑反了** —— 数据应该导入到编辑态，不是导入到快照。

**新设计**：

```
表格 = 当前编辑版本 (current_version, is_locked=0) + 历史快照 (snapshots, is_locked=1)
```

- **current_version**：永远可编辑，所有"业务流程"都在这上面
- **snapshots**：历史存档，只读
- **保存快照**：把 current 复制成 v{N+1} snapshot，同时创建 v{N+2} 新 current，更新 current_version_id
- **回滚**：从 snapshot 派生新 current，更新 current_version_id
- **导入数据**：直接到 current，不建任何中间 snapshot

## 3. 子需求

### 3.1 数据模型变更

**`generic_tables` 表加字段**：
- `current_version_id TEXT` —— 指向 `generic_table_versions.version_id`，永远指向 is_locked=0 的可编辑版本
- 兼容老库：现有表格自动把"最大 version_number 且 is_locked=0 的版本"设为 current

**`generic_table_versions` 表字段保持**：
- `is_locked INTEGER DEFAULT 0`（REQ-019 已加）
- `create_method` 字段扩展语义：
  - `'create'`：表格创建时的初始版本（is_locked=0）
  - `'snapshot'`：保存快照（is_locked=1）
  - `'rollback'`：从历史快照回滚创建的新 current（is_locked=0）
  - `'import'`：从 Excel 导入创建的新 current（is_locked=0，新设计专用）

### 3.2 模型层函数

- `set_current_version(table_id, version_id)` —— 设置表格的当前编辑版本
- `get_current_version(table_id)` —— 获取表格的当前编辑版本（带数据完整性校验）
- `save_snapshot(table_id, source_version_id, label, note, creator)` —— 把 source 复制为 snapshot，再创建新 current，更新 current_version_id
- `rollback_to(table_id, snapshot_version_id, creator)` —— 从 snapshot 派生新 current，更新 current_version_id
- `import_to_current(table_id, file_path, creator, mode)` —— 简化版 `import_rows_from_excel`，直接到 current_version

**`create_version(method, ...)` 行为调整**：
- `method='snapshot'`：创建 is_locked=1 快照（保持 REQ-019 行为）
- `method='create'`：创建 is_locked=0 初始版本（保持当前行为）
- `method='import'`：**不再使用**（导入走新路径 `import_to_current`）
- `method='rollback'`：**新增**，创建 is_locked=0 回滚版本

### 3.3 路由层调整

**`POST /api/generic-tables/<table_id>/versions`** 语义调整：
- 现有 `method='snapshot'` 调 `save_snapshot()`：自动复制 source 为 snapshot + 创建新 current + 更新 current_version_id
- 现有 `method='import'` **移除**（导入走单独路由）

**`POST /api/generic-tables/<table_id>/rollback`** 新增：
- 入参：`source_version_id`（要回滚到的历史快照）
- 行为：调 `rollback_to()`，返回新 current 的 version_id

**`POST /api/generic-tables/versions/<version_id>/rows/import`** 调整：
- 验证 `version_id` 是 current（is_locked=0），否则 403
- 直接调 `import_to_current()`，不再先建 snapshot

### 3.4 前端 UI 调整（detail.html）

**版本侧边栏**：
- 顶部标"当前编辑版本"标识（绿色徽章）
- 当前版本下显示"行 N / 列 M / 更新于 YYYY-MM-DD HH:MM / 创建人 XXX"
- 当前版本右侧有"保存快照"按钮（点击弹窗输入 label/note）
- 历史快照列表（按 version_number 倒序），每行显示 label + 创建人 + 创建时间
- 历史快照行右侧有"回滚到此"按钮（点击弹窗确认）

**工具栏**（顶部）：
- "保存快照"按钮
- "导入数据"按钮（点击直接弹文件选择，不再自动建 snapshot）
- "导出当前"按钮
- "对比历史"按钮（弹窗选快照，列出差异）

**路由跳转**：
- `/generic-tables/<table_id>/` —— 默认打开 current_version
- `/generic-tables/<table_id>/version/<version_id>/` —— 打开指定版本（**只读模式**）

### 3.5 数据迁移

**老库兼容**：
- `generic_tables.current_version_id` 通过 `ALTER TABLE` + 初始化脚本补全
- 初始化逻辑：对每个表格，找"最大 version_number 且 is_locked=0 的版本"，设为 current
- 边界情况：
  - 全部版本都 is_locked=1（没可编辑版本）→ 取最大 version_number 的版本，**强制解锁**为 current
  - 没有任何版本（不应该发生）→ 创建一个 v1 is_locked=0 作为 current

**老 URL 兼容**：
- `/generic-tables/<table_id>/` 默认打开 current_version
- 现有 `?version=<id>` URL 参数继续支持（打开指定版本只读）

## 4. 关联需求

### 4.1 与 REQ-018 的关系

REQ-018 修复了 snapshot label 格式（`v{N}_YYYYMMDD_HHMM`）和 2 处 UPDATE 加 `version_id`。**这些保留**，**新设计不需要回退 REQ-018 的修复**。

### 4.2 与 REQ-019 的关系

REQ-019 加了 is_locked 字段 + 锁定逻辑。**新设计**：
- 保留 is_locked 字段
- **保留**快照（is_locked=1）的锁定行为
- **保留**锁定拦截的 3 个操作（添加行 / 删除行 / 编辑单元格）
- **保留**不锁的 2 个操作（改色 / 列管理）
- **新增**：current（is_locked=0）永远不锁

### 4.3 与 REQ-016 的关系

REQ-016 是通用表格管理增强版。**新设计**是 REQ-016 之后的演进，**不破坏 REQ-016 已实现的功能**：
- 保留表格创建、列定义、行 CRUD、Excel 导入导出、列管理（增删改列）、改色
- 保留通用表格列表 / 详情 / 版本侧边栏 UI
- 只调整"版本"概念和相关路由

### 4.4 与现有数据

- 现有表格数据完全兼容
- 老版本的"导入前存档"快照保留（is_locked=1 只读）
- 老的 v1 初始版本（is_locked=0）保留
- 老的 create_method='import' 版本保留（is_locked 状态由初始化脚本决定）

## 5. 流程

### 5.1 主流程（管理员视角）

```
[新建表格]
   ↓
创建 v1 (create_method='create', is_locked=0)
   ↓
设置 current_version_id = v1
   ↓
[打开详情页 /generic-tables/<table_id>/]
   ↓
自动跳到 current_version
   ↓
[导入数据]
   ↓
文件上传 → 解析 → 写入 current_version
   ↓
[编辑数据 / 改色 / 列管理]
   ↓
所有操作直接落 current_version
   ↓
[点击"保存快照"]
   ↓
弹窗输入 label/note
   ↓
后端：复制 current 为 v{N+1} (method='snapshot', is_locked=1)
后端：创建 v{N+2} (method='snapshot', is_locked=0) [或复用 v{N+1} 的克隆+清空]
后端：更新 current_version_id = v{N+2}
   ↓
页面刷新，current 切换到 v{N+2}
   ↓
[继续编辑新 current]
   ↓
[点击"回滚到 v{N+1}"]
   ↓
弹窗确认
   ↓
后端：从 v{N+1} 派生 v{N+3} (method='rollback', is_locked=0)
后端：更新 current_version_id = v{N+3}
   ↓
页面刷新，current 切换到 v{N+3}，v{N+1} 数据完整复制
```

### 5.2 异常流程

- **保存快照时数据库异常**：弹窗"保存失败，请重试"，current 不变
- **回滚时源版本不存在**：返回 404，前端提示"版本不存在"
- **导入到非 current 版本**：返回 403，前端提示"只能在当前编辑版本导入"
- **current_version_id 字段为空**（数据迁移未跑）：启动时检测 + 自动修复
- **current 指向的版本被物理删除**：回退到"最大 version_number 版本" + 强制解锁

### 5.3 状态保存

- 用户的"保存快照表单输入" 用 session 暂存
- 表单弹窗关闭后清空
- 后端不缓存任何编辑状态

## 6. 场景

### 场景 1：新建表格后直接导入（**用户当前卡住的场景**）

- 用户：系统管理员
- 数据：50 行 xlsx
- 操作：
  1. 新建表格（创建 v1 is_locked=0，设为 current）
  2. 打开详情页（跳到 v1）
  3. 点"导入数据"上传 xlsx
  4. **新设计**：直接导入到 v1，v1 is_locked=0
  5. 可以继续编辑 v1（行增删改、列管理、改色）
- 预期：导入完成后用户能正常编辑，**业务流程不卡**

### 场景 2：编辑过程中保存快照

- 用户：编辑到一半想留个"基线"
- 操作：
  1. 编辑 v1（current）
  2. 点"保存快照" → 弹窗输入"导入第一批" → 确认
  3. 后端：复制 v1 为 v2 (snapshot, is_locked=1)，创建 v3 (current, is_locked=0)
  4. 页面跳到 v3，v3 内容 = v2 内容
  5. 继续编辑 v3
- 预期：v2 永远只读保存"导入第一批"基线，v3 继续作为 current 可编辑

### 场景 3：发现 v3 改错了，从 v2 回滚

- 用户：v3 误改了 10 行
- 操作：
  1. 看版本列表 v2 标识"导入第一批"
  2. 点"回滚到此" → 弹窗确认"基于 v2 创建新 current"
  3. 后端：复制 v2 为 v4 (rollback, is_locked=0)
  4. 页面跳到 v4，v4 内容 = v2 完整复制
- 预期：v4 是新 current 可编辑，v2 保留只读

### 场景 4：对比 v3 和 v1 的差异

- 用户：想知道改了哪些行
- 操作：
  1. 点"对比历史" → 弹窗选 v1
  2. 后端返回 v1 vs v3 的行差异（新增/删除/修改/改色）
  3. 展示差异列表
- 预期：看到完整的"什么改了"

### 场景 5：老数据迁移（兼容性）

- 数据：现有 5 个表格，每个有 1-3 个版本，部分版本是 snapshot (is_locked=1)
- 操作：跑数据迁移脚本
- 行为：
  - table 1：v1 (create, is_locked=0) → current = v1
  - table 2：v1 (create, is_locked=0) + v2 (snapshot, is_locked=1) → current = v1
  - table 3：v1 (create, is_locked=0) + v2 (snapshot, is_locked=1) + v3 (import, is_locked=1) → current = v1（最大 is_locked=0 仍是 v1）
  - table 4：v1 (snapshot, is_locked=1) + v2 (snapshot, is_locked=1)（异常，全部锁定）→ 取 v2 强制解锁为 current
- 预期：所有表格都有 current，老数据不丢失

### 场景 6：导入数据到历史快照（边界）

- 用户：不小心在 v2 (snapshot) 详情页点"导入"
- 操作：调 `POST /api/.../versions/<v2_id>/rows/import`
- 行为：后端校验 `v2.is_locked=1`，返回 403
- 预期：前端提示"只能在当前编辑版本导入，请回到 current"

### 场景 7：批量保存快照（性能）

- 用户：一天内保存 50 次快照
- 操作：连续 50 次"保存快照"
- 行为：每次都正确创建 snapshot + new current
- 预期：版本号 v1, v2, v3, ... v100 都能正常切换，不卡顿
