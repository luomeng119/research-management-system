# REQ-020 通用表格版本快照重新设计

## 1. 背景

04 科研管理系统"通用表格管理"模块（REQ-016 增强版）目前支持"按版本管理"和"创建快照"。**但版本和快照的关系设计有问题**：

- 新建表格后，导入数据时，前端先自动创建一个 method='snapshot' 的"导入前存档"版本，再把数据导入到这个新快照里
- REQ-019 加了 is_locked 字段，快照版本 is_locked=1
- 导入完成后，用户看到的就是 locked 快照，**不能编辑**，业务流程卡死

**根因**：当前没有"编辑态"概念。每个版本要么是空的 v1（刚建表），要么是 locked 快照，**永远没有可编辑的"当前态"**。

## 2. 目标

重新设计通用表格的版本/快照概念：
- 引入 **current_version（编辑态）** 概念
- 表格永远有"当前编辑版本"（is_locked=0），所有编辑/导入/回滚操作都在 current 上
- 快照是历史存档（is_locked=1），只读不可改
- 用户所有"业务流程"都基于 current_version，不需要手动管理版本

## 3. 用户场景

- 场景 A：新建表格后直接导入数据，期待可以继续编辑
- 场景 B：编辑过程中想保存当前状态作为历史快照（防止误改），但不影响继续编辑
- 场景 C：发现当前数据有问题，想从某个历史快照回滚到那个版本继续编辑
- 场景 D：对比当前编辑版本和某个历史快照的差异

## 4. 功能范围

### 4.1 必须实现
- 表格 schema 加 `current_version_id` 字段，指向可编辑版本
- 任何表格打开时，自动定位到 current_version
- 所有编辑操作（行增删改、列管理、改色、导入数据）都在 current_version 上
- "保存快照"按钮：把 current 复制成 v{N+1} 快照（is_locked=1），同时创建 v{N+2} 新 current（is_locked=0），更新 current_version_id 指向新 current
- "回滚"按钮：选历史快照 → 复制为新 v{N+3} current（is_locked=0），更新 current_version_id
- "对比"功能：选 current vs 某个历史快照，列出差异

### 4.2 必须不实现
- 离线编辑 / 自动保存（保持手动"保存快照"语义）
- 多人协同编辑（同一时刻只有一人编辑 current）
- 快照合并（保持快照只读，回滚就是创建新 current）
- 复杂权限控制（保持全员可编辑/查看）

## 5. 限制与边界

- 历史快照永远只读（is_locked=1 强制锁定行/列/单元格）
- 一次只能有一个 current_version
- 导入数据不再自动建"导入前存档"快照（用户如果想保留旧数据，先手动保存快照再导入）
- 数据迁移：现有表格统一把"最大版本号的 is_locked=0 版本"设为 current（多数情况下是 v1；如有 v2 是 create_method=import 的，解锁 v2 设为 current）

## 6. 权限与流程

- 保留现有权限：全员可创建/编辑/查看通用表格
- 保留 REQ-019 的锁定逻辑：快照行/列/单元格不能改
- 保留"编辑色"和"列管理"在快照上不可改的规则
- 保留"添加行/删除行/编辑单元格"在 current 上可用

## 7. 不在本期范围

- 自动保存/草稿箱
- 版本回退（只能创建新 current，不能物理删除老快照）
- 协作编辑冲突解决
- 表格导出时的版本选择（默认导出 current，需要扩展再说）
