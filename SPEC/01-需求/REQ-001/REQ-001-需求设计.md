## 一、用户描述整理复述

### 分类报销（来自 REQ-001）

> 目前报销助手没有区分报销类型，统一进行发票上传、自动/手动匹配、生成报销项目等。需要进行分类报销。

报销类型：出差报销 / 采购报销

发票类型：高铁票、飞机票、网约车发票、出租车发票、增值税专用发票、增值税普通发票、通用机打发票、定额发票、采购发票、其他

### 信息展示优化（来自 REQ-002）

> 待整理发票和记录中文件名，报销项的"内容"需改成发票中的有实际含义的"项目名称"或者"规格型号""交易场所"等信息。

---

## 二、功能理解

**分类报销**：报销助手目前不区分报销类型，所有发票统一处理。需要新增报销类型分类（出差报销/采购报销），让报销流程更贴合实际业务场景。

**信息展示优化**：待整理区列表和报销项详情中，"文件名"列无业务含义，应替换为发票/支付记录中有意义的字段（品名、规格、销售方等）。

**本质**：两个需求都是对报销列表 UI 的优化——一个改变数据结构（报销类型），一个优化展示内容。

## 五、流程分析

### 5.1 发票上传后自动分类流程

```
用户上传发票
    ↓
OCR 识别（recognize_invoice）
    ↓ 提取 invoice_type
自动判断报销类型：
  - invoice_type ∈ {高铁票, 飞机票, 网约车, 出租车} → 出差报销
  - 否则 → 采购报销
    ↓
存入 expense_invoice，报销类型记录在内存/界面状态
```

### 5.2 报销项创建流程

```
用户点击"新建报销项"
    ↓
选择报销类型（默认「采购报销」，草稿时可切换）
    ↓
从待整理区选择发票 + 支付记录
    ↓
点击"生成报销项目"
    ↓
自动判断报销类型（根据已选发票 invoice_type）
    ↓
存入数据库，status='draft'
```

### 5.3 待整理区信息展示流程

```
加载待整理发票列表
    ↓
显示优先级：items[0].name + items[0].spec > seller > invoice_type > "-"
    ↓
加载待整理支付记录列表
    ↓
显示收款方（payer，OCR提取或手动）> "-"
```

## 六、场景分析

### 场景1：出差报销

用户出差回来，上传高铁票 + 酒店发票 + 出租车票
→ 系统自动判定为「出差报销」
→ 用户选择这三张发票，生成报销项目

### 场景2：采购报销

用户采购办公用品，上传增值税普通发票
→ 系统自动判定为「采购报销」
→ 用户选择发票，生成报销项目

### 场景3：混合报销

用户同时有出差发票和采购发票
→ 目前按"就高原则"：有任一出差类发票 → 出差报销；全为采购类 → 采购报销

### 场景4：旧数据兼容

已存在的报销项目/发票无报销类型字段
→ 默认为空/null，界面显示「—」或按采购报销处理

## 开发规则（已确认）

1. **报销项创建默认「采购报销」**
2. **自动匹配类型判定**：根据发票 invoice_type 自动判断报销类型（高铁票/飞机票/网约车/出租车→出差报销，否则采购报销）
3. **待整理发票区不需要区分报销类型**
4. **草稿状态可切换报销类型，已确认不可切换**
5. **发票列表和支付记录列表上下排列，不使用 Tab 切换**
