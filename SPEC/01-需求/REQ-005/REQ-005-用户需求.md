# REQ-005：报销单据自动填充增强（OCR火车票/航空票提取）

## 用户需求

### 背景
报销助手已支持从发票/支付记录自动填充差旅费报销凭证的部分字段。
新建「因公出差审批单」时，用户仍需手动填写出行信息。

### 需求描述
对「新建单据」功能中的「因公出差审批单」，优化自动填充功能：
通过 OCR 识别已上传的火车票、航空行程单，**自动提取**以下字段：

| 审批单字段 | OCR来源 | 说明 |
|-----------|---------|------|
| 到达单位及地点 | 火车票到达站 / 航空行程单到达机场 | 取任一张有效票据的到达地点 |
| 起止时间 | 火车票/航空行程单的时间 | 取最早出发时间 ~ 最晚到达时间 |
| 出行方式 | 票据类型 | 高铁（G/D）、飞机（航空行程单），混用时注明「高铁/飞机」 |

### 业务规则
1. 报销项下有多张火车票/航空票时：
   - 到达地点：取**最后到达**的地点（多日出差可能多段）
   - 起止时间：取**最早出发日期时间 ~ 最晚到达日期时间**
   - 出行方式：高铁票优先「高铁」；同时有高铁和飞机时「高铁/飞机」
2. OCR 提取失败时，该字段保持空值，由用户手动填写（不做降级猜测）
3. 已上传的发票/支付记录，在「自动填充」前需先完成 OCR 识别

---

## 6 维需求设计

### 维度1：业务需求
- 用户选择「因公出差审批单」模板后，点击「自动填充」按钮
- 系统从该报销项关联的发票（火车票/航空行程单）中 OCR 提取出行信息
- 将提取结果回填到对应字段，字段来源标注为 `invoice:火车票.到达站` 等

### 维度2：UI/交互
- 自动填充后，每个字段旁显示 badge 说明数据来源（例：`invoice:G322.到达站(1条)`）
- 如果某字段无数据可填充，badge 显示 `user_input`
- 发票/支付记录已 OCR 识别的，可直接使用；未识别的先触发识别再填充

### 维度3：数据模型
**新增 `expense_invoice` 表字段：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `train_no` | TEXT | 车次（如 G37、G322） |
| `departure_station` | TEXT | 出发站（如 北京南） |
| `arrival_station` | TEXT | 到达站（如 上海虹桥） |
| `seat_type` | TEXT | 座位类型（如 二等座） |
| `flight_no` | TEXT | 航班号 |
| `departure_airport` | TEXT | 出发机场 |
| `arrival_airport` | TEXT | 到达机场 |
| `travel_date` | TEXT | 出行日期（YYYY-MM-DD） |
| `travel_time` | TEXT | 出发时间（HH:MM） |

**模板字段 `source` 扩展：**
- `invoice:火车票.到达站` → 填充 `arrival_station`
- `invoice:火车票.出发站` → 填充 `departure_station`
- `invoice:火车票.车次` → 填充 `train_no`
- `invoice:火车票.出发时间` → 填充 `travel_time`
- `invoice:火车票.出行日期` → 填充 `travel_date`
- `invoice:航空行程单.到达站` → 填充 `arrival_airport`
- `invoice:航空行程单.航班号` → 填充 `flight_no`
- `invoice:出行方式` → 特殊逻辑，根据票据类型组合判断

### 维度4：技术方案
1. **OCR 层**（`app/ocr/recognizer.py`）：
   - 增强 `extract_invoice_fields()` 函数，识别火车票/航空行程单后提取结构化出行字段
   - 使用正则从 OCR 文本中提取：车次、出发站、到达站、座位、日期、时间、航班号等

2. **数据库层**（`app/expense_db.py`）：
   - `expense_invoice` 表 ALTER TABLE 添加新字段
   - `save_invoice()` / `update_invoice()` 支持新字段写入
   - `get_invoices()` 返回数据中包含新字段

3. **自动填充层**（`app/routes/documents.py` `api_auto_fill`）：
   - 扩展字段 source 解析，支持 `invoice:火车票.*` 和 `invoice:航空行程单.*` 类型
   - 聚合多张票据的时间，取最早~最晚
   - 出行方式根据票据类型组合确定

### 维度5：接口设计
`POST /expense/documents/api/reimbursements/<rid>/documents/auto_fill`
请求体：
```json
{
  "doc_type": "因公出差审批单",
  "fields": {}
}
```
响应体（扩展）：
```json
{
  "success": true,
  "suggestions": {
    "T2[1,1]": { "value": "上海虹桥", "source": "invoice:火车票.到达站 (2条)", "locked": false },
    "T2[2,1]": { "value": "2026-04-15 07:52 ~ 2026-04-15 19:25", "source": "invoice:火车票.起止时间 (2条)", "locked": false },
    "T2[3,1]": { "value": "高铁", "source": "invoice:出行方式 (高铁×2)", "locked": false }
  },
  "available_invoices": [...],
  "available_payments": [...]
}
```

### 维度6：验收标准
1. 上传 2 张火车票（G322、G37 北京南→上海虹桥）后，创建「因公出差审批单」
2. 点击「自动填充」，系统 OCR 识别两张票据
3. 「到达单位及地点」字段自动填充「上海虹桥」
4. 「起止时间」字段自动填充「2026-04-15 07:52 ~ 2026-04-15 19:25」
5. 「出行方式」字段自动填充「高铁」
6. 各字段 badge 显示正确的 source 说明
