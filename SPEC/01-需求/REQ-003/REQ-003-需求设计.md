# REQ-003 需求分析：报销项目列表优化

## 状态

**阶段二（需求分析）— 已确认**

---

## 一、需求描述（用户语言复述）

用户希望对报销项目列表做"减法"和"增强"：
- **减**：去掉使用频率低的信息列（编号、三单），让界面更清爽
- **改**：时间列改名+改含义，使其业务语义更清晰；报销状态简化，改为手工切换的「已报销/未报销」二元状态
- **增**：展开后的发票和支付记录明细行，增加鼠标悬浮预览卡片

---

## 二、子需求分析

| 子需求编号 | 内容 | 用户目的 |
|------------|------|---------|
| REQ-003-F1 | 删除编号列 | 编号对用户无业务意义，仅开发侧有用 |
| REQ-003-F2 | 标题可修改 | 报销项创建后，发现标题不准确，需要能改 |
| REQ-003-F3 | 删除三单列 | 三单指示器占了一列，用 hover 卡片替代更节省空间 |
| REQ-003-F4 | 时间→开支时间 | 报销的"时间"应反映实际支出时间，而非系统记录时间 |
| REQ-003-F5 | 状态→已/未报销 | 原有"草稿/已确认/已生成文档/已完成"过于复杂，用户只关心"报销了没有" |
| REQ-003-F6 | 展开区明细hover卡片 | 查看发票/支付明细时，直接 hover 就能看到完整详情，不用点开文件 |

## 四、使用流程分析

```
用户打开报销页面
    ↓
浏览报销项列表（金额/类型/开支时间）
    ↓
点击 ▶ 展开报销项
    ↓
想了解某张发票的完整信息 → hover 该行 → 显示详情卡片
想了解某条支付记录的完整信息 → hover 该行 → 显示详情卡片
    ↓
发现标题有误 → 点击标题 → 行内编辑 → 失焦保存
    ↓
款项打出后 → 点击「未报销」→「已报销」
```

## 五、场景分析

| 场景 | 描述 |
|------|------|
| 日常浏览 | 用户打开页面快速扫视报销项列表，金额/类型/开支时间是最关注的信息 |
| 核对发票明细 | 报销前核对发票内容，hover 展开区的发票行快速查看完整信息 |
| 修改标题 | 创建时报错标题写错，事后需要更正 |
| 标记完成 | 款已打，财务手工标记"已报销" |
