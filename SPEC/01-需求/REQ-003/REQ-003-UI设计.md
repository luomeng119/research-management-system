## 二、主列表结构

```
│ ▼ │ 编号 │ 标题         │ 金额   │ 发票 │ 支付 │ 状态   │ 类型 │ 三单       │ 时间     │ 操作          │

**优化后（9列）：**

```
│ ▼ │ 标题              │ 金额   │ 发票 │ 支付 │ 状态(已/未报销) │ 类型 │ 开支时间 │ 操作          │

## 四、交互细节

| 交互 | 行为 |
|------|------|
| 标题编辑 | 点击标题 → span 替换为 input → 失焦调用 API 保存 → 恢复只读；编辑中按 ESC 取消 |
| 状态切换 | 点击「○未报销」或「●已报销」→ 调用 toggle_paid API → 立即更新显示 |
| 发票行 hover | 鼠标进入发票行 → 300ms 延迟 → 显示卡片 → 离开后隐藏 |
| 支付行 hover | 同发票行逻辑 |
| 开支时间 | 取关联发票 date 和支付记录 pay_date 中的最晚值，无关联显示 "—" |

## 五、状态映射

| 现有 status 值 | 现有语义 | 新 is_paid 值 | 新语义 |
|---------------|---------|--------------|--------|
| 草稿 | 未提交 | 0 | 未报销 |
| 已确认 | 待打款 | 0 | 未报销 |
| 已生成文档 | 已生成结算单 | 0 | 未报销 |
| 已完成 | 款已打出 | 1 | 已报销 |

**说明：** is_paid 由用户手工切换，不自动跟随 status 变化。
