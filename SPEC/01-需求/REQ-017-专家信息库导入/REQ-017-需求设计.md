# REQ-017 需求设计

## 1. 用户描述复述

> 04 科研管理系统，专家信息库，增加一个导入功能。实现逻辑参照设备知识库的导入功能，分步骤，要支持列映射调整和选择。

**关键约束**（用户补充确认）：
- 必填字段：name 必填
- expert_id 不可导入、不可手工填充（系统自动生成）
- 列映射智能提示
- 导入上限 1000 条
- 不需要异步进度

## 2. 功能理解

按用户描述的"实现逻辑参照设备知识库的导入功能，分步骤"，专家导入应复用设备导入的三步式流程：

- 步骤 1：上传文件 + 解析表头 + 用户调整列映射 + 智能预选
- 步骤 2：解析每行 + 校验必填 + 逐行确认/跳过/修改
- 步骤 3：批量提交 + 结果展示

但**专家表字段比设备表简单**：
- 设备表有 24 个字段含 4 个必填（equipment_id、name、category、subclass）
- 设备表有"研制单位"等多值字段需要智能匹配
- 设备表有"分类"枚举字段需要批量选择
- 设备表有"关联设备"等复杂关联

专家表只有 10 个可导入字段、1 个必填（name）、无多值/枚举/关联字段。

**因此**：
- 复用设备导入的**整体框架**（路由结构、模板布局、JS 交互模式、SSE 进度机制）
- **简化**设备导入里"智能匹配单位、分类选择、关联设备"三块复杂功能
- **保留**设备导入里"列映射、必填校验、逐行确认、批量提交"四块核心能力

## 3. 子需求

### 3.1 入口可见

- 专家列表页（/experts/）右上角增加"导入"按钮
- 点击后跳转 /experts/import（步骤 1）
- **全员可见**——所有登录用户都能看到入口和执行导入，不做角色限制

### 3.2 步骤 1：上传 + 列映射

- 上传 .xlsx 文件（拖拽或点击）
- 上传后自动调用 preview_only 接口，解析表头
- 显示 Excel 前 10 行预览表格
- 显示**列映射下拉组**——每个 Excel 列对应一个下拉框
- 下拉框选项：10 个可导入字段 + 1 个"忽略此列"
- 智能预选：按"列名包含关键字"规则预选（用户需求 §6）
- 列名不含任何关键字的列，默认"忽略此列"
- 同一字段被多列选时，自动把后选的列改为"忽略此列"（避免冲突）
- 实时校验：name 字段必须被某个 Excel 列映射，否则"下一步"按钮置灰

### 3.3 步骤 2：逐行确认

- 按列映射解析每行数据
- name 缺失或全空白的行：标"跳过（缺姓名）"、自动选"跳过"、不可改为"确认"
- 其他行：标"待确认"、默认选"确认"、可改为"跳过"
- 每行显示解析后的字段值（供用户对照原 Excel 内容）
- 单行右侧有"修改"按钮，点击展开行内编辑（可改 name / unit / phone / id_card 等）
- 顶部"全选"按钮：把所有"待确认"行批量设为"确认"
- 顶部"反选"按钮：把所有"待确认"行批量设为"跳过"
- 底部"确认导入"按钮：把"确认"行批量写入数据库
- 底部"取消导入"按钮：返回步骤 1

### 3.4 步骤 3：结果展示

- 显示统计：成功 X 条 / 跳过 Y 条 / 失败 Z 条
- 成功列表：显示前 100 条的姓名 + 单位 + 生成的 expert_id
- 失败列表：显示所有失败行 + 失败原因（缺姓名 / 写入异常 / expert_id 冲突）
- 底部"返回列表"按钮：跳 /experts/

### 3.5 expert_id 自动生成

- 格式：`EXP-yyyyMMdd-XXXX`
- 生成时机：写入数据库前，每条记录单独生成
- 流水号生成：查今天所有 `EXP-yyyyMMdd-*` 记录的最大流水号 +1
- 同批次多条记录：按数组顺序递增流水号（避免数据库并发写冲突）
- 极端情况：当天已超过 9999 条 → 报错"今日导入已达上限，请明日再试"

## 4. 关联需求

### 4.1 与设备导入的关系

- **复用**：路由分层模式（GET 入口 / POST preview / POST commit）、模板布局（顶部步骤指示器 / 中部内容区 / 底部按钮区）、JS 交互（fetch + JSON）
- **简化**：去掉"研制单位智能匹配""关联设备选择""分类枚举选择"三块
- **不同**：expert_id 不接受导入值，由系统生成；无"分类"概念所以没有"批量分类选择"

### 4.2 与现有专家 CRUD 的关系

- 写入路径：走 ExpertModel.insert()，与"添加"页面走同一条路径
- expert_id 自动生成逻辑**独立于** ExpertModel.insert()，在调用前生成
- 不改 ExpertModel 的现有方法（向后兼容）

### 4.3 与权限系统

- **全员可导入**——不限制角色，所有登录用户都能看到入口和执行导入
- 不需要新增角色
- 不需要审计日志（本期不做）

## 5. 流程

### 5.1 主流程（管理员视角）

```
[列表页 /experts/]  → 点击"导入"  → [步骤 1: /experts/import]
                                            ↓
                                       拖拽 / 点击上传 .xlsx
                                            ↓
                                    preview_only 解析表头 + 前 10 行
                                            ↓
                                    显示列映射下拉（智能预选）
                                            ↓
                                    用户调整列映射
                                            ↓
                                    点击"下一步"
                                            ↓
                                       [步骤 2: /experts/import/preview]
                                            ↓
                                    解析全部行（按列映射）
                                            ↓
                                    校验必填 name，标跳过/待确认
                                            ↓
                                    用户逐行操作（确认/跳过/修改）
                                            ↓
                                    点击"确认导入"
                                            ↓
                                       写入数据库
                                            ↓
                                       [步骤 3: /experts/import/done]
                                            ↓
                                    显示成功/跳过/失败统计
                                            ↓
                                    点击"返回列表"
                                            ↓
                                    [列表页 /experts/]
```

### 5.2 异常流程

- 上传非 .xlsx：步骤 1 提示"请上传 xlsx 文件"，按钮不变灰
- 列映射必填校验失败：步骤 1 的"下一步"按钮置灰 + 提示"姓名列未映射"
- 数据行数 = 0：步骤 1 提示"文件无数据行"
- 数据行数 > 1000：步骤 1 提示"超出 1000 条上限，请拆分"
- 文件 > 20MB：步骤 1 提示"文件过大（>20MB）"
- 文件含合并单元格：按 openpyxl 默认行为（保留首格值，其余为 None），不报错
- 步骤 2 解析时数据库异常：步骤 3 显示失败列表 + 错误堆栈前 200 字符

### 5.3 状态保存

- 文件上传后，解析结果保存在 session（`session['expert_import_preview']`）
- session 大小限制 4KB（Flask 默认 cookie 存 session）
- 数据量大时改用 server-side session 或临时文件（本期先评估，本期默认用 session）
- 步骤切换不丢失数据（用户回到步骤 1 改列映射，预览数据保留）

## 6. 场景

### 场景 1：标准 50 人批量导入（最常见）

- 用户：系统管理员
- 数据：单位提供 50 人的 Excel 名册，含姓名/单位/职务/电话/身份证号 5 列
- 操作：上传 → 智能预选全部 5 列 → 调整（确认无误）→ 下一步 → 50 行全显示"待确认"→ 批量确认 → 导入
- 预期：步骤 3 显示"成功 50 / 跳过 0 / 失败 0"，列表页多 50 条

### 场景 2：列名不规范需要手动调整

- 用户：系统管理员
- 数据：Excel 列名是"老王""老李""科室""座机"等不规范名称
- 操作：上传 → 智能预选一个都匹配不上（下拉全"忽略此列"）→ 手动把"老王"映射到 name、"科室"映射到 unit → 下一步
- 预期：步骤 2 只显示手动映射的字段，其他列被忽略

### 场景 3：部分行缺姓名

- 用户：系统管理员
- 数据：100 行，其中 3 行姓名列为空
- 操作：上传 → 智能预选 → 下一步 → 步骤 2 显示 100 行，其中 3 行标"跳过（缺姓名）"且不可改为"确认"
- 预期：导入时 3 行被跳过，97 行成功，步骤 3 显示"成功 97 / 跳过 3"

### 场景 4：超过 1000 条

- 用户：系统管理员
- 数据：1500 行
- 操作：上传 → 步骤 1 提示"超出 1000 条上限，请拆分"
- 预期：步骤 1 的"下一步"按钮置灰，提示用户拆分

### 场景 5：上传空文件

- 用户：误操作上传了只有表头的文件
- 操作：上传 → preview_only 返回 0 行
- 预期：步骤 1 提示"文件无数据行"，下一步按钮置灰

### 场景 6：上传 .xls 老格式

- 用户：用了 Excel 2003 保存的 .xls
- 操作：上传 → 后端拒绝
- 预期：步骤 1 提示"请上传 xlsx 格式"，按钮不变灰

### 场景 7：导入后想撤销

- 用户：发现导入了 5 条重复（虽然是自动 expert_id，但 name 重复）
- 操作：步骤 3 完成后，点击"返回列表" → 列表看到 50 条 → 用"姓名"搜索 → 找到重复 5 条 → 逐条删除
- 预期：删除走现有 ExpertModel.delete()，不需要新增"撤销导入"功能
