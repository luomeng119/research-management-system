# REQ-004 需求设计：报销单据模板管理

## 基本信息

- **需求编号**：REQ-004
- **需求名称**：报销单据模板管理
- **状态**：阶段二（需求设计）— 已确认

---

## 一、用户描述整理复述

**用户补充确认**：
1. **自动填充后支持手动更改**：报销人核对自动提取的数据后，可自由修改任意字段
2. **多单据+多发票+多支付记录 → 完整报销项目 → 输出一份可打印文档**

用户原需求：
> 对采购申请表、出差审批单、差旅费报销凭证、途中伙食补助费申请表等进行**模板的管理**，支撑报销结算使用。入口设想：**替换审批单台账**。

**复述确认**：
- 4 种单据类型的模板维护（增删改查）
- 模板定义字段结构、填写说明、提取规则
- 报销人从模板发起单据时，从已有发票/支付记录中**自动提取**相关信息填充
- **自动填充后报销人可手动修改任意字段**
- **报销项目 = 多张单据 + 多张发票 + 多张支付记录，最终汇总输出为一份完整可打印文档**
- 新入口替换现有"审批单台账"菜单
- 旧审批单台账数据**废弃**，无需迁移

---

## 二、功能理解

**核心问题**：
1. 报销人每次填写单据时，需要从发票/支付记录中手工摘抄数据，容易出错、效率低
2. 一个报销项目涉及多种单据、多个发票、多个支付记录，最终需要整合成一份完整文档打印归档

**解决思路**：
- 管理员预先定义好每种单据的模板（含字段提取规则）
- 报销人选择模板发起时，系统从已上传的发票/支付记录中自动提取数据填充到单据字段
- **报销人核对后可手动修改**
- **报销项目下可附加多种单据，最终汇总为一份可打印文档**

**本质**：模板 + 规则引擎（自动填充）+ 报销项目汇总打印

## 三、子需求分析

### REQ-004-A：模板管理（管理员）

| 功能 | 说明 |
|------|------|
| 查看模板列表 | 按类型分组展示所有模板 |
| 新增模板 | 选择单据类型，定义字段结构、填写说明、提取规则 |
| 编辑模板 | 修改已有模板 |
| 删除模板 | 移除模板 |
| 预览模板 | 查看模板的字段结构和说明 |

### REQ-004-B：4种单据模板定义

每种单据需定义：

| 单据类型 | 建议字段 | 可自动提取的字段 |
|---------|---------|---------------|
| 采购申请表 | 采购物品名称、规格型号、数量、单价、合计金额、供应商、用途说明、申请人、申请日期 | 合计金额（从支付记录）、供应商（从发票 seller） |
| 出差审批单 | 出差人姓名、部门、目的、地点、出发日期、返回日期、交通工具、住宿标准、预算合计、申请人、申请日期 | 出发/返回日期（从已有出差审批）、预算合计（计算） |
| 差旅费报销凭证 | 报销人、部门、出差日期区间、机票/火车票金额、住宿费金额、餐费补贴、其他费用、合计金额、收款账户 | 机票/火车票金额（从发票 amount）、住宿费（从支付记录）、合计（从支付记录 amount） |
| 途中伙食补助费申请表 | 姓名、部门、出发日期、到达日期、途经地点、补助天数、补助标准、补助金额 | 补助天数（从日期计算）、出发/到达日期（从出差审批单） |

**提取规则定义格式**（每个字段可配置）：
```
字段名 | 来源(invoice/payment/计算) | 匹配条件 | 映射关系
```

### REQ-004-C：从模板发起并自动填充（报销人）

| 功能 | 说明 |
|------|------|
| 选择模板类型 | 从4种单据中选择 |
| 指定数据范围 | 选择关联的报销项（rid） |
| 自动提取执行 | 根据模板的提取规则，从匹配的发票/支付记录中提取数据 |
| 填充预览 | 显示提取到的数据，供报销人确认/修改 |
| **手动修改** | **自动填充后，报销人可手动修改任意字段** |
| 保存到报销项 | 将填写好的单据**附加到报销项**下 |

### REQ-004-D：报销项目汇总文档（核心输出）

| 功能 | 说明 |
|------|------|
| 报销项目附加单据 | 一个报销项目可附加多张不同类型的单据 |
| 汇总打印 | 报销项目 = 多张单据 + 多张发票 + 多张支付记录 → **汇总输出为一份完整可打印文档** |
| 文档结构 | 封面 + 目录 + 各单据内容 + 发票粘贴页 + 支付记录粘贴页 + 合计金额页 |
| 打印排版 | 按报销项目组织，适合纸质归档 |

### REQ-004-E：菜单入口替换

- 将现有的"审批单台账"菜单项替换为"报销单据"
- 普通用户看到："新建单据" + "我的报销项目"
- 管理员额外看到："模板管理"

## 五、流程分析

### 流程 A：管理员维护模板

```
管理员进入"模板管理"
    ↓
选择单据类型（如"差旅费报销凭证"）
    ↓
定义字段列表（名称、类型：文本/金额/日期、填写说明）
    ↓
为每个字段配置提取规则（来源、匹配条件）
    ↓
保存模板
```

### 流程 B：报销人从模板发起单据

```
报销人进入"报销单据" → "新建单据"
    ↓
选择单据类型（如"差旅费报销凭证"）
    ↓
选择关联报销项（rid）
    ↓
点击"自动提取"
    ↓
系统根据模板提取规则，从关联发票/支付记录中提取数据
    ↓
展示填充预览
    ↓
报销人核对/手动修改
    ↓
保存 → 单据附加到报销项下
```

### 流程 C：报销项目汇总打印

```
报销人进入"我的报销项目"
    ↓
选择报销项（如"4月出差报销"）
    ↓
点击"汇总打印"
    ↓
系统汇总：
  - 该报销项下的所有附加单据
  - 所有关联发票
  - 所有关联支付记录
  - 合计金额
    ↓
生成并展示完整文档（适合打印）
```

### 流程 D：菜单替换

```
用户点击"报销单据"菜单
    ↓
展示"模板管理"（管理员）或"新建单据"（普通用户）
    ↓
"审批单台账"菜单项隐藏或移除
```

## 六、场景分析

### 场景 1：管理员首次配置模板

- **前置条件**：系统刚上线，无模板数据
- **操作**：管理员进入模板管理，点击"新增模板"，选择"差旅费报销凭证"，添加字段，设置提取规则，保存
- **边界**：字段名称重复时提示；提取规则来源字段不存在时提示

### 场景 2：报销人使用模板自动填充

- **前置条件**：已有上传的发票和支付记录关联到某报销项
- **操作**：报销人选择报销项，点击自动提取，系统填入发票金额、供应商等信息
- **边界**：
  - 无关联发票/支付记录 → 提示"无可提取数据"
  - 多个匹配记录 → 提示"找到 N 条，请选择"
  - 金额单位不一致 → 需统一处理（元）

### 场景 3：报销人修改自动填充的数据

- **前置条件**：自动提取后，报销人发现个别字段不准确
- **操作**：报销人直接编辑已填充的字段
- **边界**：编辑后再次提取会覆盖，需提示"将覆盖已有修改"

### 场景 4：报销项目汇总打印

- **前置条件**：报销人已在某报销项下附加了多张单据
- **操作**：报销人点击"汇总打印"，系统生成完整文档
- **边界**：
  - 无单据/发票/支付记录 → 提示"无内容可打印"
  - 文档过长 → 分页合理，支持 A4 打印

### 场景 5：模板字段变更

- **前置条件**：已有模板在使用中
- **操作**：管理员修改模板字段
- **边界**：不影响已附加到报销项的单据；仅对新发起单据生效
