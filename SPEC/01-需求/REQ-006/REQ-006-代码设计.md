## 数据库变更

无需新增数据库表。数据来源：
- `expense_reimbursement`：`reimbursement_type`（类别）用于模板选择
- `expense_invoice`：`amount`（金额汇总→申报金额），`date`（日期→出差日期）
- `expense_payment`：`file_path`（附件区）

## 主要函数/接口

### 后端路由（app/routes/documents.py）

**新路由**：
```
POST /expense/documents/api/reimbursements/<int:rid>/generate_report
```

**处理流程**：
1. 鉴权（session 检查）
2. 查 `expense_reimbursement` 表获取 `reimbursement_type`
3. 根据类别选择模板路径：
   - 出差报销 → `报销单模板/出差完整报销单据模板.docx`
   - 物资采购（或其他） → `app/document_templates/科研物资采购申请单/模板.docx`
4. 查发票（`expense_invoice`）和支付记录（`expense_payment`）
5. 构造 `field_values`（发票金额汇总、日期等）
6. 调用 `DocumentFiller.generate()` 生成 docx
7. 调用 `_append_attachments_to_docx()` 将支付记录 PDF/图片附加到文档末尾
8. 保存到 `documents/{reimb_no}_{timestamp}_完整报销单.docx`
9. 返回文件下载

**新函数**：
- `api_generate_report(rid)` - 主路由
- `_append_attachments_to_docx(docx_bytes, payments)` - 将支付记录附件追加到 docx 末尾（复用 `_pdf_or_image_to_png_bytes`）
- `_build_report_context(rid)` - 构建模板填充上下文（金额汇总、日期等）

## 关键设计决策

1. **模板选择**：通过报销单的 `reimbursement_type` 字段判断
2. **字段填充**：通过 `DocumentFiller.generate(doc_type, field_values, context)` 填充，field_values 从发票 OCR 数据构造
3. **附件追加**：复用 `_pdf_or_image_to_png_bytes` 将 PDF 转 PNG 后，用 `docx` 库的 `add_picture()` 追加到文档末尾
4. **文件保存**：保存到报销项目 `documents/` 目录，文件名含时间戳

## 边界处理

| 场景 | 处理方式 |
|------|---------|
| `reimbursement_type` 为空/未知 | 回退到物资采购模板 |
| 无发票/支付记录 | 生成空白单据（模板填充空值） |
| 支付记录含 PDF | PDF 转 PNG 后附加（复用已有逻辑） |
| 文件名冲突 | 时间戳精确到秒，理论上无冲突 |
